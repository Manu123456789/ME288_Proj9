SIMULINK TRAJECTORY PROPAGATOR
ASCII implementation guide for the five-sheet schematic
===============================================================================

Based on Simulink_Trajectory_Propagator_Schematic.pdf.

Build the shared acceleration subsystem first. Then choose the continuous
Integrator model or the discrete Heun loop. Both use the same force functions
and produce position, velocity, physical time, gravity, and drag histories.

1. CREATE THE MODEL AND DEFINE THE SIGNALS
===============================================================================

Create a blank Simulink model. Make the case inputs and table arrays available
to the model through the MATLAB workspace, model workspace, or data dictionary.

  Case input   Size       Meaning
  ----------   --------   -----------------------------------------------------
  R_0          [3 x 1]    Initial ECI position in m
  V_0          [3 x 1]    Initial ECI velocity in m/s
  t_0          Scalar     Physical time of the initial state in s
  t_f          Scalar     Requested physical end time in s
  dt_nom       Scalar     Positive nominal step in s. Use abs(dt) from MATLAB.

The model advances six states, [R; V]. R and V are three-element columns in
Earth-centered inertial (ECI) coordinates. Use your existing state conversion
at the appropriate epoch if the input data is Earth-fixed. Use the altitude
and aerodynamic table conventions of your source data. Convert units where
the data enters the model.

Use the times to select direction. A case with t_0 = 0 and t_f = -20 goes
backward by 20 s. A case with t_0 = 5 and t_f = -15 also goes backward by
20 s. For t_f = t_0, the trajectory consists of the initial sample.

The MATLAB interface maps to the model as follows.

  propagate_traj(R_0, V_0, t_0, t_f, dt)
    R_0, V_0    -> initial conditions
    t_0, t_f    -> physical time and duration
    abs(dt)     -> nominal step, or a cap on the variable solver step
    R, V, time  <- position, velocity, and physical time logs
    acc_grav, acc_drag <- separate physical acceleration logs


2. BUILD THE SHARED ACCELERATION SUBSYSTEM
===============================================================================

Add a Subsystem named Accel with Inports R, V, and t. Place the gravity
calculation and a Drag Subsystem inside it. Use a Sum block with signs ++.
Give Accel outputs a_total, a_grav, and a_drag so you can log the components.

  R -------> [Gravity] -------- a_grav ----.
                                           +--> [Sum ++] --> a_total
  R, V, t -> [Drag Subsystem] -- a_drag ---'

  MATLAB operation               Simulink block        Ports
  ----------------------------   -------------------   ------------------------
  AccelGrav(R)                   MATLAB Function       R -> a_grav [3 x 1]
  Altitude(R)                    MATLAB Function       R -> H (scalar)
  Atmosphere(H)                  MATLAB Function       H -> rho, a_sound
  Drag(R,V,t)                    Subsystem             R, V, t -> a_drag
  interp1(Mtable,Cdtable,Mach)     1-D Lookup Table      Mach -> legacy value
  Validated axial lookup         n-D Lookup Table      Table axes -> C_A0

Altitude and Atmosphere sit inside Drag. The name a_sound identifies the
local speed of sound. a_total is the vector sum of the physical accelerations.
For scheduled table changes, add a mode input to Accel and pass it to Drag.

Wrap callable MATLAB routines with MATLAB Function blocks. Double-click the
block and enter the appropriate function below. The arguments in each function
signature become its input and output ports. Use your actual routine names
and signatures. Set vector port sizes to [3 1] where needed and adapt a
routine's row or column convention inside the wrapper.

  Gravity block

    function a_grav = fcn(R)
        a_grav = AccelGrav(R);
    end

  Altitude block

    function H = fcn(R)
        H = Altitude(R);
    end

  Atmosphere block

    function [rho, a_sound] = fcn(H)
        [rho, a_sound] = Atmosphere(H);
    end

Direct calls use code-generation-compatible MATLAB routines on the MATLAB
path. If the gravity routine is local to propagate_traj.m, expose it as a
callable function, for example in AccelGrav.m. If the implementation already
lives in a named Simulink Function, use a Function Caller with the matching
Function prototype, for example a_grav = AccelGrav(R). Match argument names,
types, and dimensions.

For the continuous model, set the force-path MATLAB Function wrappers'
Update method to Continuous so their outputs are evaluated at intermediate
solver states. For the discrete loop, let the wrappers inherit the rate
of the sampled states. The same force calculations serve both Heun stages.


3. WIRE THE DRAG SUBSYSTEM
===============================================================================

Add Inports R, V, and physical t, and an Outport a_drag. Wire the atmosphere
and relative-velocity path first.

  Output                           Block and input connections
  ------------------------------   --------------------------------------------
  H = Altitude(R)                  MATLAB Function, input R
  rho, a_sound = Atmosphere(H)     MATLAB Function, input H
  V_rot = cross(omega_E, R)         Cross Product, omega_E first, R second
  V_atm = V_rot + W                Sum (++), V_rot and W
  u = V - V_atm                    Sum (+-), V at +, V_atm at -
  U = sqrt(dot(u,u))               Dot Product with u at both inputs, then Sqrt

rho is air density in kg/m^3. a_sound is in m/s. Use your existing Earth
rotation vector omega_E in rad/s. W is wind relative to the co-rotating
atmosphere, expressed as a three-element ECI vector in m/s. Use W = [0;0;0]
for co-rotating still air. If Atmosphere provides wind, expose it as another
output. Convert the wind to ECI before the Sum block. For altitude-only
profiles, use one 1-D Lookup Table per property with H as the common input.

u is the object's velocity relative to the air. U is its magnitude. Compute
the scalar flow quantities with Product, Divide, and Gain blocks.

  Mach = U / a_sound
  qbar = 0.5 * rho * U^2
  Re   = rho * U * L_ref / mu

Use U at both Product inputs to get U^2, then multiply by rho and apply a
Gain of 0.5. qbar is dynamic pressure in Pa. For Re, use the reference length
L_ref in m and dynamic viscosity mu in Pa*s from the table's convention.
Supply mu directly or compute it with the temperature model you use for the
source data. For a unit Reynolds number grid, use rho * U / mu in the grid's
declared inverse-length units.

At U = 0, return a_drag = [0;0;0]. Set an If block to u1 > 0 with U as its
input and enable Else. Put the lookup and the u/U calculation in the first
If Action Subsystem and the zero vector in the other. Merge their outputs.

Legacy Mach-only lookup

  Block                       1-D Lookup Table
  Breakpoints 1               Mtable, the Mach grid
  Table data                  Cdtable, the stored values
  Input port                  Mach, computed from U / a_sound
  Interpolation               Linear, to match the three-argument interp1 call

The stored value is whatever the legacy table contains. Trace it through
one existing drag calculation. A value that directly divides qbar to give
acceleration magnitude in SI serves as beta in kg/m^2. A dimensionless
coefficient goes through the existing normalization. Match the legacy
out-of-grid behavior when checking parity. The default linear interp1 call
returns NaN outside its grid. Flag those samples explicitly in the model.

Validated axial lookup

  1. Add an n-D Lookup Table. Set the number of dimensions to the number
     of source axes. For H, Mach, Re, use three input ports.
  2. Set the breakpoints and Table data from the validated arrays. Each
     table dimension must match the length of its breakpoint vector.
     Wire the inputs in the source array's axis order.
  3. For a Mach, incidence, Re table, connect zero to the incidence port
     or use the zero-incidence slice with its corresponding breakpoints.
     Match the source interpolation and flag queries outside the grid.
  4. Route dimensionless axial C_A0 through your legacy normalization.
     With positive drag coefficients and existing area-to-mass factor
     K_norm, the relation is 1/beta_nom = C_A0 * K_norm. If the source
     provides beta directly, route it to beta_nom.

If there are scheduled table changes, pass the mode signal into Drag. One
implementation uses Switch Case, a Switch Case Action Subsystem for each
table, and a Merge for the active lookup output. Use a numeric mode ID for
each table and pass the flow quantities into its lookup subsystem.

Drag acceleration

  u_hat    = u / U
  a_nom    = -(qbar / beta_nom) * u_hat
  a_drag   = s * a_nom
  beta_eff = beta_nom / s

Divide the vector u by U. Divide qbar by beta_nom, apply the minus sign,
and multiply that scalar by u_hat. The minus sign points the force against
the air-relative velocity. With C_A0 * K_norm available directly, use
qbar * (C_A0 * K_norm) for the positive acceleration magnitude. The drag
correction Gain is s. Start with s = 1 and log C_A0 when available, beta_nom,
s, beta_eff, and the selected mode. Keep s distinct from the time direction
gain sigma.


4. BUILD THE CONTINUOUS PROPAGATOR
===============================================================================

This version uses two continuous Integrator blocks and one Accel subsystem.
Simulink handles the intermediate evaluations and the state updates.

  T     = abs(t_f - t_0)
  sigma = sign(t_f - t_0)
  t     = t_0 + sigma * tau

In Model Settings > Solver set Start time to 0 and Stop time to T. The
Simulink Clock outputs tau, which increases from 0 to T. Connect Clock to
a Gain of sigma and then a Bias of t_0 to obtain physical t. Route t to
Drag and to a named log signal t_phys.

  a_total = Accel(R,V,t)
  dV/dtau = sigma * a_total
  dR/dtau = sigma * V

  [Accel] -- a_total --> [Gain sigma] --> [Integrator IC V_0] -- V --.
                                                                     |
  R <-- [Integrator IC R_0] <-- [Gain sigma] <-----------------------'

Feed R and V back to the Accel inputs. Set the Integrator initial conditions
to V_0 for velocity and R_0 for position. Feed the physical V output to the
second Gain. Log R, V, t_phys, a_grav, and a_drag. Tap a_grav and a_drag
before the direction Gain so they keep their physical signs in either run.

Choose either solver in Model Settings > Solver using that wiring.

  Setting                    Variable-step             Fixed-step
  ------------------------   -----------------------   -----------------------
  Type                       Variable-step             Fixed-step
  Solver                     ode45 (Dormand-Prince)    ode4 (Runge-Kutta)
  Step setting               Max step size             Fixed-step size
  Starting value             dt_nom                    Positive h
  Accuracy check             Tighten tolerances and    Halve h and compare
                             reduce Max step size      on the same time grid

ode45 is adaptive. Set Relative tolerance, Absolute tolerance, and Max
step size in Solver details. ode4 uses fourth-order RK4 at the fixed
step h. Choose h so T is an integer multiple of h to land on t_f. If the
step can be adjusted, h = T / ceil(T / dt_nom) gives a step at or below
dt_nom and aligns the endpoint.

Scheduled table switches

Run an integration segment to the switch time using the active table for
that segment. A Constant block can supply its mode. For the next run, use
the last R and V as initial conditions, set t_0 to the switch time, and
select the next mode in the propagation direction. Recompute T and sigma
for that segment. With ode4, align each segment duration to its step. Keep
a single state sample at the join and carry the mode alongside any
discontinuous force or coefficient logs.


5. BUILD THE DISCRETE HEUN PROPAGATOR
===============================================================================

Set Solver Type to Fixed-step and select the discrete solver. Set Fixed-step
size and the Unit Delay Sample time to dt_nom. Use Start time 0 and Stop time
inf. The Stop Simulation block terminates the run at the requested physical
endpoint.

  [Unit Delay] -> [Unpack state] -> [Predictor] -> [Corrector and update]
       ^                                                         |
       '---------------------- [Pack next state] <---------------'

Set the Unit Delay Initial condition to [R_0; V_0; t_0]. Use Selector blocks
to take entries 1:3 as R_k, 4:6 as V_k, and 7 as t_k. Use Vector Concatenate
to pack [R_next; V_next; t_next] at the input of the Unit Delay.

Determine the signed physical step from the currently accepted t_k.

  goal = t_f
  r    = goal - t_k
  h    = sign(r) * min(dt_nom, abs(r))

  If abs(r) <= dt_nom, set t_p = goal exactly.
  Otherwise set t_p = t_k + h.

For a scheduled table change, set goal to the first upcoming switch on the
path from t_k to t_f, if one lies on that path. A switch at the current
t_k has already been reached. For each nonzero step, select the table from
the physical segment midpoint t_k + 0.5*h and send that mode to both Accel
instances. For example, if A is active before t_switch and B afterward,
select A when the midpoint is less than t_switch and B otherwise. This
uses the correct side of the boundary in either propagation direction.

Use two instances of the same Accel implementation. Evaluate Stage 1 at
the accepted state and Stage 2 at the predicted state.

  Predictor
    a1  = Accel(R_k, V_k, t_k)
    R_p = R_k + h * V_k
    V_p = V_k + h * a1

  Corrector and update
    a2     = Accel(R_p, V_p, t_p)
    R_next = R_k + (h/2) * (V_k + V_p)
    V_next = V_k + (h/2) * (a1 + a2)
    t_next = t_p

Here a1 and a2 are the a_total outputs. Implement the equations with Sum
and Product blocks or a small MATLAB Function block. Heun averages the
two signed derivatives, so the direction comes from h. Check constant
gravity before comparing to the old MATLAB implementation.

Log the Unit Delay outputs R_k, V_k, and t_k, with the physical gravity and
drag evaluated at that accepted state. Name the time log t_phys. Connect
the comparison t_k == t_f to Stop Simulation. Because the last step sets
t_p to t_f explicitly, the next tick logs the exact terminal state and
then stops. At that tick, set x_next = x_k and use the final segment's
mode for the force logs. Use t_phys for analysis when a step is shortened.


6. CHECK THE MODEL AND RUN THE TRUTH CASES
===============================================================================

Check the integration and signs first with constant acceleration. Feed the
acceleration path a_grav = [0;0;-10] m/s^2 and a_drag = [0;0;0] for this test.
Set R_0 = [0;0;0] m, V_0 = [100;0;0] m/s, and t_0 = 0 s.

  t_f      Expected R at t_f (m)      Expected V at t_f (m/s)
  ------   -----------------------    -----------------------
   2 s     [ 200; 0; -20]             [100; 0; -20]
  -2 s     [-200; 0; -20]             [100; 0;  20]

Use dt_nom = 0.3 s to exercise the shortened final Heun step. Use h = 0.1 s
for an aligned ode4 check. The velocity sign change and the direction of
the position shift check that sigma or h is applied in the right places.

Check the drag path at a known R, V, and physical t. Compare H, rho, U,
Mach, qbar, the lookup result, and a_drag with your MATLAB calculation.
For a simple arithmetic check with u = [100;0;0] m/s, rho = 1.2 kg/m^3,
a_sound = 300 m/s, beta_nom = 200 kg/m^2, and s = 1, expect Mach = 1/3,
qbar = 6000 Pa, and a_drag = [-30;0;0] m/s^2. Check the zero-speed branch
and the selected table at a known switch. Match the Mach-only baseline
before using the validated axial lookup.

Run the integrator comparison with identical initial conditions and force
models. Refine dt_nom for Heun, tighten tolerances and reduce the maximum
step for ode45, or halve h for ode4. Compare the resulting R and V at the
same physical timestamps. Compare solver-to-solver differences with the
errors against truth to see how much the integrator choice moves the result.

Batch validation

  1. Enable Signal logging in Model Settings > Data Import/Export. Mark
     the named signals R, V, t_phys, a_grav, and a_drag for logging. Add
     Mach, Re, mode, and the available lookup diagnostics for force checks.
     With Single simulation output, the default Dataset is out.logsout.
  2. For each truth case, supply R_0, V_0, t_0, t_f, and dt_nom. Use the truth
     state at t_0 for the initialization. Use one model run per case, or
     one run per segment when a continuous case has a table switch.
  3. Export physical t as an N-by-1 column and R and V as N-by-3 matrices.
     Use a consistent frame, units, and time origin for model and truth.
     Use ascending time for interpolation, reversing backward histories
     and the corresponding signal rows together.
  4. Interpolate the simulation at truth timestamps within the overlap.
     Keep the reference samples on their own timestamps. Evaluate force
     and coefficient comparisons on the matching side of each mode switch.
  5. At each matched sample compute e_R = norm(R_sim - R_truth) and
     e_V = norm(V_sim - V_truth). Report RMS = sqrt(mean(e.^2)), peak error,
     and error at a matched t_f for each case. For a backward run t_f is
     the earlier end of the physical history. Apply your margins per case.
  6. Compare beta with beta or C_A0 with the corresponding axial
     coefficient, and match the Reynolds number convention. Summarize
     the per-case RMS, peak, and endpoint values across truth runs to show
     the spread.

For workspace case variables, a minimal run pattern is

    in = Simulink.SimulationInput(mdl);
    in = in.setVariable('R_0', caseData.R_0(:));
    in = in.setVariable('V_0', caseData.V_0(:));
    in = in.setVariable('t_0', caseData.t_0);
    in = in.setVariable('t_f', caseData.t_f);
    in = in.setVariable('dt_nom', caseData.dt_nom);
    out = sim(in);
    tLog = getElement(out.logsout, 't_phys');
    time = tLog.Values.Data(:);

Use mdl as the model name and caseData as the struct for one truth case.
If variables live in a model workspace, specify that workspace with
setVariable(..., 'Workspace', mdl). Read R and V from the Dataset by
their signal names and arrange the samples as rows. For a comparator using
sim.time and sim.signals, put the logged physical time in sim.time and the
state and force arrays in sim.signals using the comparator's field names.

If you calibrate s, fit a shared positive gain using matched-state
along-flow truth acceleration when it is available. With trajectory-only
truth, fit using normalized position and velocity errors. Evaluate the
fitted gain on held-out truth cases.
